# FSearch

**轻量、准确、注重响应速度的桌面文件搜索工具——基于 Rust 与 egui。**

[English](README.md) · [简体中文](README.zh-CN.md) · [开发规范 / AGENTS](AGENTS.md)

> **当前状态：egui 桌面 MVP，而非已经实现 Everything 式索引的版本。** 目前具备图形界面、后台目录扫描、会话内存缓存查询和兼容的 CLI。**持久化索引、Windows NTFS/MFT 快速枚举、USN Journal 增量更新、真正的模糊匹配与文件变更监听均未实现**，属于后续开发目标。

## 设计目标

FSearch 希望做到 **快、准、轻、小而美**：

- **高响应性**：扫描和查询放在后台线程，通过输入防抖和虚拟化列表减少 UI 阻塞。
- **准确**：明确区分文件名精确匹配、完整路径精确匹配、文件名子串和路径子串。
- **轻量**：Rust 搜索核心，egui / eframe 桌面界面，避免无关框架和冗余功能。
- **路径可靠**：扫描、匹配与系统文件操作保留原始 `PathBuf` / `OsStr`，扫描部分失败不丢弃已发现结果。
- **跨平台目标**：计划支持 Windows、Linux、macOS；特定能力和可用性需要按实际系统验证。

默认定位是**文件名与路径搜索**，而不是全文文件内容搜索器。

## 已实现的功能

| 功能 | 状态 | 说明 |
| --- | --- | --- |
| 桌面图形界面 | 已实现 | egui / eframe 0.36.2，Glow / OpenGL |
| 递归目录扫描 | 已实现 | 迭代扫描、原生路径；默认不跟随目录符号链接或 Windows reparse point |
| 文件名/完整路径精确匹配 | 已实现 | 两种独立模式，区分大小写 |
| 文件名/完整路径子串匹配 | 已实现 | 连续字面子串匹配，**不是**模糊匹配 |
| 后台搜索 | 已实现 | 175 ms 输入防抖；同一次扫描的结果在当前会话中复用 |
| 进度与取消 | 已实现 | 协作式取消，无法中断已在进行的系统 I/O |
| 搜索结果操作 | 已实现 | 原始路径排序、虚拟列表、文件/目录过滤、打开/定位/复制 |
| 外观设置 | 仅当前会话 | 深浅主题、缩放、English/中文（中文依赖本机 CJK 字体） |
| 持久化磁盘索引 | **未实现** | 程序重启后需要重新扫描 |
| NTFS MFT / USN 追踪 | **未实现** | Windows 专用高性能索引后端的规划 |
| 真正的模糊匹配 | **未实现** | 后续实现非连续匹配和相关性评分 |
| 自动感知文件变更 | **未实现** | 目前需要重新扫描更新缓存 |

桌面最多**展示 20,000 条匹配结果**，同时保存全部命中数量。这只是**显示上限，不是扫描内存上限**。当前全量扫描结果仍保存在内存中，尚未提供可复现的大规模性能测量数据。

## 快速开始

### 环境要求

- 已安装 Rust stable 和 Cargo；桌面 crate 声明 **最低 Rust 1.95**。
- 可用的桌面窗口环境、OpenGL/Glow，以及平台常规原生构建依赖。
- Windows、Linux、macOS 为目标系统，但 CI 矩阵配置并不等于三个平台的 GUI 都已完成实际运行验收。

```bash
git clone https://github.com/ananwanan/fsearch.git
cd fsearch
```

### 运行桌面程序

```bash
cargo run -p fsearch-desktop --release --locked
```

**不带参数启动时**，搜索范围会预填当前工作目录，但**不会自动扫描**。可粘贴路径，或拖入文件/文件夹，然后主动开始扫描；目前没有系统原生文件夹选择对话框。

带参数启动时可指定目录并立即扫描：

```bash
cargo run -p fsearch-desktop --release --locked -- \
  --directory ./crates \
  --query search \
  --mode name-substring
```

| 参数 | 简写 | 用途 |
| --- | --- | --- |
| `--directory PATH` | `-d` | 可选起始路径；传入后自动扫描 |
| `--query TEXT` | `-q` | 初始搜索文字，默认为空 |
| `--mode MODE` | 无 | `exact-name`、`exact-path`、`name-substring`（默认）、`path-substring` |

当前所有搜索模式都**区分大小写**。

### 快捷键

| 快捷键 | 操作 |
| --- | --- |
| `Ctrl+L` | 聚焦搜索框 |
| `↑` / `↓` | 在搜索结果中移动选中项 |
| `Enter` / 双击 | 打开选中的文件或目录 |
| `Ctrl+Shift+C` | 复制选中项路径 |
| `Ctrl+O` | 在文件管理器中定位或打开所在目录 |
| `Ctrl+R` | 重新扫描 |
| `Escape` | 取消当前任务；空闲时清空搜索文字 |

macOS 上相应命令快捷键使用 **Cmd**；界面也提供鼠标操作。

### 运行 CLI

旧的命令行程序依然保留，可执行文件/包名为 **`search`**。仓库根目录默认 Cargo 成员仍是 CLI：

```bash
cargo run --release --locked -- --directory ./crates --filename search.rs
```

也可以显式使用 `cargo run -p search --release --locked -- ...`。

| 必填参数 | 简写 | 当前含义 |
| --- | --- | --- |
| `--directory PATH` | `-d` | 起始目录或已有文件路径 |
| `--filename TEXT` | `-f` | **在完整候选路径中查找区分大小写的连续字面子串** |

`--filename` 是历史参数名，并不代表只搜索文件名；CLI 也尚未开放桌面的四种模式选项。搜索结果由 Rust `dbg!` 输出到 **stderr**。

CLI 的状态约定：合法但无匹配返回退出码 `0`；合法空目录输出 `File list not found` 并返回 `0`；根路径错误返回 `1`；子项错误会输出 `Scan incomplete`、保留已发现匹配且返回 `1`；参数错误由 clap 返回 `2`。

## 四种搜索模式的实际语义

以下功能已经存在于 `fsearch-core`：

| 模式 | 例子 | 行为 |
| --- | --- | --- |
| `ExactName` | `report.pdf` | 文件名最后一个路径分量完全相等 |
| `ExactPath` | `reports/report.pdf` | 与原始完整路径字符串的原生表示完全相等 |
| `NameSubstring` | `port.p` | 在最终文件名中查找连续片段 |
| `PathSubstring` | `reports` | 在完整路径中查找连续片段 |

当前不会自动进行路径规范化、Unicode 规范化或大小写折叠；空子串查询会匹配已扫描的全部适用条目。**不支持**通配符、正则表达式、拼写纠错和相关性评分。

将来的 `Fuzzy` 模式可以支持非连续字符的有序匹配，例如输入 `rptpdf`，命中 `report.pdf`；这必须是单独定义和测试的新模式，不能把已有的 `contains` 子串搜索换个名字就称作模糊搜索。

## 当前工作方式

```text
                  egui / eframe
                        │
                 UI 命令与事件
                        │
                  后台工作线程
                   /          \
             迭代扫描       字面匹配
                   \          /
                   会话内存快照
                        │
                  筛选、虚拟列表
```

项目采用 Rust 2021 Cargo workspace：

```text
crates/
  fsearch-core/       无外部依赖的文件系统扫描及搜索核心
  fsearch-cli/        兼容命令行工具（可执行文件：search）
  fsearch-desktop/    egui 界面、后台任务、系统文件操作
```

**现在的缓存只是当前会话的扫描结果。** 用户更改查询不会重新访问整棵目录，但程序重启不会恢复缓存；文件变化后必须主动重新扫描。它不是 Everything 式的持久化或实时增量索引。

## 下一阶段：借鉴 Everything 的索引机制

FSearch 的方向是**先建立索引，随后反复查询索引，并在文件发生变化时增量维护**，而不是每输入一个字就遍历整个目录。

1. **统一索引基础**：把可查询的内存索引从扫描报告中独立出来，定义文件身份、索引新鲜度、内存控制、批量发布与可复现的性能测试。
2. **Windows NTFS 快速后端**：评估使用 `FSCTL_ENUM_USN_DATA` 从 NTFS 文件记录（MFT 元数据）高效枚举文件，使用 `FSCTL_QUERY_USN_JOURNAL` 和 `FSCTL_READ_USN_JOURNAL` 获取增量变化；正确处理父目录关系、重命名、硬链接、日志重置/缺口、离线卷及索引重建。
3. **跨平台回退**：Linux、macOS、非 NTFS 卷、网络路径，以及无权读取 NTFS 卷时继续使用通用目录扫描；以后引入的文件监听必须支持事件丢失后的校准或重扫。
4. **真正的模糊搜索**：独立的匹配算法、评分与稳定排序，明确大小写和 Unicode 策略，并进行性能回归测试。
5. **持久化与体验完善**：可崩溃恢复、版本化的索引文件，排除规则与设置持久化，索引过期状态、跨平台验证、安装包与性能基准。

**权限与隐私**：读取 NTFS 卷级元数据可能需要更高权限，但不应因此要求整个 egui 界面以管理员身份运行。若未来引入辅助服务，需要严格限制权限并确保本地 IPC 安全；同时保留普通用户可用的目录扫描后端。默认只索引文件名、路径和必要元数据，不自动索引文件内容。

详细实现约束与开发阶段见 [AGENTS.md](AGENTS.md)。

## 已知限制

- 没有真正的 fuzzy、持久化索引、文件监听、可配置大小写策略、原生路径选择器，以及排除规则和设置的持久化。
- 非 UTF-8 路径在界面展示或文本复制时可能有损，但扫描、匹配、打开操作保留系统原始路径。
- 并发文件变化可能使扫描结果不是严格快照；局部访问错误会单独报告，会话缓存随后也可能过时。
- 取消采用协作方式，大规模目录扫描的内存开销仍随条目数量增长；20,000 条显示上限并不限制内存。
- Linux 的“定位”目前只是打开父目录，不保证选中条目；Windows 的当前定位 API 存在 259 个 UTF-16 单元的路径长度限制。
- 各平台仍需进一步真实验证。旧开发记录提到 2026-10-11 的 Windows 本地检查，但不能由此推断当前仓库在 Linux/macOS 的运行结果或未测量的性能数字。

cargo build --workspace --release --locked
