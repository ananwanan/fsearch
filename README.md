# FSearch

**轻量、快速、准确的桌面文件搜索工具。**

FSearch 旨在使用 **Rust + egui / eframe** 打造一款“小而美”的跨平台文件搜索软件：快速定位文件，既支持严格的精确搜索，也支持容错的模糊匹配；保持简洁的界面、低资源占用和流畅的交互。

> **项目状态：早期 CLI 原型。** 当前仓库尚未实现 egui 图形界面、真正的模糊匹配、文件索引或后台实时搜索。下文会明确区分当前能力和规划功能。

## 设计理念

- **高效率**：扫描、查询、排序分离；未来通过索引和后台工作线程提升大规模文件集下的响应能力。
- **精确搜索**：明确区分文件名完全匹配与完整路径完全匹配。
- **模糊匹配**：规划支持不连续字符的模糊命中和相关性排序，不局限于简单子串查找。
- **小而美**：egui 原生桌面 GUI、紧凑布局、良好的键盘操作与一致的视觉风格。
- **跨平台**：目标覆盖 Windows、Linux 和 macOS；各平台支持状态以实际构建与测试为准。
- **可靠性**：尊重文件系统原始路径，正确应对权限、Unicode、深目录、符号链接及扫描期间的文件变动。

## 当前已实现

仓库目前采用 **Rust 2021**，依赖 `clap` 提供简单 CLI：
- 支持传入起始目录并递归枚举子目录下的条目。
- 支持以**区分大小写的子串匹配**查找：目前查询针对**完整路径字符串**，并非仅文件名。
- 使用 `dbg!` 输出匹配结果；调试构建时额外输出耗时。
- 现有 GitHub Actions 运行基本构建和测试工作流。

**目前的限制**：
- 命令行尚无搜索模式参数：`main.rs` 固定调用 `find_file(..., Some(false))`。
- 内部 exact 分支是完整路径字符串相等，不是文件名精确匹配。
- `contains` 只是连续子串匹配，不属于真正的 fuzzy search。
- 没有索引和文件系统变更监听；每次运行都重新递归遍历。
- 尚未提供 GUI、后台扫描、取消搜索及持久化设置。
- 现有遍历实现对某些 I/O 错误、符号链接循环与非 UTF-8 路径等边界情况尚不完善。

## 运行当前 CLI 原型

### 环境

安装 Rust stable 与 Cargo。当前程序无需 egui 环境，因为 GUI 还未引入。

```bash
git clone https://github.com/ananwanan/fsearch.git
cd fsearch
cargo run --release -- --directory . --filename Cargo
```

两个必填参数：

| 参数 | 简写 | 当前含义 |
| --- | --- | --- |
| `--directory` | `-d` | 递归遍历的起始目录，也可为现有文件路径 |
| `--filename` | `-f` | 在完整路径中查找的区分大小写连续子串 |

例如：

```bash
cargo run --release -- -d ./src -f helper
```

注意：示例展示的是**已有 CLI**，其输出仍是调试格式。`--filename` 这个参数名并不代表目前只搜索 basename。

## 目标功能（尚未实现）

| 功能 | 期望行为 |
| --- | --- |
| 文件名精确搜索 | 输入 `report.pdf` 只匹配同名文件（可配置大小写规则） |
| 完整路径精确搜索 | 按定义明确的路径规则查询唯一位置 |
| 子串搜索 | 输入 `report` 查找文件名包含连续片段的条目 |

| egui 图形界面 | 搜索框、模式选择、范围设置、结果列表、搜索进度和状态反馈 |
| 非阻塞交互 | 后台查询、输入防抖、可取消任务、虚拟滚动及结果分批更新 |
| 实用操作 | Enter 打开文件、复制路径、打开所在目录、键盘导航 |
| 个性化 | 浅色/深色主题、缩放、过滤规则与设置持久化 |

以上是**路线图与设计目标**，不是当前版本的已实现功能或性能承诺。

## 规划中的程序架构

```text
                  ┌──────────────────────────┐
                  │      egui / eframe       │
                  │  输入 · 结果 · 交互 · 设置 │
                  └────────────┬─────────────┘
                               │ 消息 / 状态
                  ┌────────────▼─────────────┐
                  │     Search service       │
                  │ 模式 · 匹配 · 评分 · 排序  │
                  └────────────┬─────────────┘
                               │ 查询
                  ┌────────────▼─────────────┐
                  │    Scanner / Index       │
                  │ 扫描 · 过滤 · 索引 · 更新  │
                  └────────────┬─────────────┘
                               │
                         File system
```

设计原则：**搜索引擎独立于 GUI**；扫描、索引和昂贵的查询运行在后台，不能阻塞 egui 的绘制循环。索引/缓存格式采用可演进的数据模型，优先正确性，再通过可复现基准数据进行优化。

## 开发路线

1. **P0 — 搜索核心**：补齐测试、明确精确/子串语义、健壮路径遍历和错误处理。
2. **P1 — egui MVP**：建立桌面 GUI、搜索模式切换、后台扫描、结果呈现和键盘操作。
3. **P2 — 性能升级**：可复用索引、真正的模糊匹配与评分、增量刷新、查询取消和性能基准。
4. **P3 — 发布质量**：文件变更追踪、设置持久化、跨平台回归测试、打包和视觉细节。
